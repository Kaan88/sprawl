**S1 #4, by tool.** The distinction that matters here is whether the **whole cleanup** stays within the reviewed directory. A flag can win its precedence check and still control only one of several destinations. (`crates/sprawl-advisor/src/clean.rs:414`)

- **pnpm — hold it.** In pnpm 10.20.0, pruning removes metadata directories under a separate `cacheDir` and also cleans expired `dlx` entries there. `--store-dir` can select the intended store perfectly while both operations remain outside it. Holding pnpm is the smallest fix until every removal destination is constrained for supported versions. [pnpm store controller](https://raw.githubusercontent.com/pnpm/pnpm/v10.20.0/store/package-store/src/storeController/prune.ts) · [pnpm prune command](https://raw.githubusercontent.com/pnpm/pnpm/v10.20.0/store/plugin-commands-store/src/storePrune.ts)
- **Yarn Classic — the flag wins, but the probe and cleanup name different scopes.** Yarn 1.22.22 prefers the explicit cache folder. `cache dir` prints the versioned child, while an unqualified `cache clean` recursively removes the configured **parent**. Sprawl's final exclusion check and hold apply to the child. A sharing failure can occur after sibling data has already been removed. Yarn initialization can also create the cache and temp directories during the probe, before Sprawl acquires its hold. Hold Yarn, or validate and hold its full cleanup root before either invocation and account for partial failure. (`crates/sprawl-advisor/src/clean.rs:470`) · [Yarn configuration](https://raw.githubusercontent.com/yarnpkg/yarn/v1.22.22/src/config.js) · [Yarn cache commands](https://raw.githubusercontent.com/yarnpkg/yarn/v1.22.22/src/cli/commands/cache.js)
- **Go — `GOCACHE` wins for the build cache.** Inherited or saved `GOFLAGS` can independently enable additional cleanup targets. The `go env GOCACHE` probe does not report them. Neutralize ambient Go flags and their configuration-file fallback for both processes, or hold Go. [Go environment precedence](https://go.dev/src/cmd/go/internal/cfg/cfg.go) · [Go flag handling](https://go.dev/src/cmd/go/internal/base/goflags.go) · [Go cleanup targets](https://raw.githubusercontent.com/golang/go/master/src/cmd/go/internal/clean/clean.go)
- **npm — the cache binding is sound for cached packages.** npm also rotates logs in an independently configurable `logs-dir`, including during ordinary CLI initialization. Bind its log directory to a checked location for both invocations. Setting the log count to zero alone still permits old-log cleanup in the implementation inspected. [npm configuration](https://docs.npmjs.com/cli/v11/using-npm/config/) · [npm log cleanup](https://raw.githubusercontent.com/npm/cli/latest/lib/utils/log-file.js)
- **pip and NuGet — the purge destinations have the stated precedence.** pip's command-line `--cache-dir` wins over environment and file settings. NuGet's `NUGET_PACKAGES` wins over `globalPackagesFolder`, and Sprawl selects only `global-packages`. **Conda — keep it held.** Its `--all` operation covers multiple categories and writable caches. [pip precedence](https://pip.pypa.io/en/stable/topics/configuration/) · [NuGet configuration](https://learn.microsoft.com/en-us/nuget/reference/nuget-config-file) · [Conda cleanup targets](https://docs.conda.io/projects/conda/en/stable/commands/clean.html)

**Other per-user writes from S1 #1 — partly fixed.** Keeping the elevated request log is acceptable with a stable parent and leaf. `open_own` checks a plain, single-link file, but explicitly allows delete sharing. Its name can change after the final-path check. The parent has only the attribute-level hold discussed below, and rotation resolves its destination by pathname. The same parent gap affects clearing `searches.txt`, although the final deletion now uses the opened handle. Hold the actual parent before opening or creating the leaf, exclude competing renames through append or removal, and rotate relative to that parent. **New logging regression:** overlapping appends can fail because each writer denies write sharing, and `log_request` discards the error. Serialize or retry if every outgoing request is meant to be recorded. `crates/sprawl-advisor/src/store.rs:88` · `:109` · `crates/sprawl-advisor/src/llm/mod.rs:270` · `crates/sprawl/src/search_query.rs:656`

**New `local::pin()` finding — confirmed.** Give callers two explicit operations. A caller that will reopen a name needs a sharing-enforced hold on that leaf. A caller that will rename or delete needs a stable parent and a checked target handle with its own mutation rights. Making every validation handle block deletion would break legitimate callers. One concrete consumer is compression: it checks a file through `storage()` and later gives its pathname to `compact.exe`. That file needs to stay bound to its name through the command. `crates/sprawl-core/src/local.rs:232` · `crates/sprawl-advisor/src/remedies.rs:188`
