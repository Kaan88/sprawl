# Sprawl 0.2.5: product, safety and usability audit

Date: 2026-11-17. Commit audited: `3eec3d0`. Read-only: nothing was changed, deleted, cleaned or uninstalled.

**Superseded in part by `audit-2026-11-17-final.md`.** After this report was written: the uninstaller in the brief was a mistake (section 7, UNI-1 to UNI-4 and the Apps view are not gaps), accessibility and the number of map views are out of scope for now, and the roadmap in section 16 is replaced by the final report's. The findings themselves stand; SAF-1 and CLN-2 were later confirmed by a real clean-up.

Path shorthand: `app/` = `crates/sprawl/src/`, `adv/` = `crates/sprawl-advisor/src/`, `core/` = `crates/sprawl-core/src/`, `TOML` = `crates/sprawl-advisor/rules/builtin.toml`.

Evidence labels used throughout:

- **Confirmed**: I read the code or saw it in the running app myself.
- **Code review**: reported by one of four area reviewers from reading the code; not re-checked by me line by line.
- **Unverified**: a concern that needs a run or a measurement; the check is named.
- **Opportunity**: a product idea, not a defect.

## 1. Executive summary

**What the product is.** The brief describes an uninstaller, a BleachBit-style cleaner, an Everything-style search and an advisory AI. The product is something else: a disk-space analyser (WizTree-class: tree, file list, file types, treemap) that has grown an Advisor, a Cleaners tab, a Search tab and an optional AI. There is no uninstaller. "Uninstall…" opens Windows' Installed apps, Steam, or a program the user names.

**Strongest elements.**

- The deletion engine is careful: every item passes `safety::check` twice, deletes are handle-based, links are never followed, a never-list protects Windows and profiles, and packs that are not built in can never be green, ticked for the user, or carry a command.
- The AI is contained. It cannot delete, run a command or tick anything. Its findings are checked against the scan, floored at orange and labelled.
- Search never runs on the UI thread, discards stale results, and keeps Delete away from rows that are not part of the scan (with one hole, below).
- The analyser core (scan, tree, treemap, file types) is fast, legible and complete.
- Candour in the UI: "Deleted for good, not sent to the Recycle Bin", "paths … are sent to the provider as they are".

**Most serious problems.**

1. **The clean-up review makes a promise the code does not keep.** It says "anything new since the scan is left alone"; the executor deletes whatever is in the folder at run time, permanently (SAF-1, Confirmed).
2. **Enter or Down in the search box can crash the app or aim Delete at an unrelated file** (SAF-2, Confirmed).
3. **A saved API key is sent to any address typed in the AI settings, including plain http** (SAF-3, Confirmed).
4. **"Keep" does not protect anything from a clean-up**, and "Save as a script" adds items the user did not tick (SAF-4, SAF-5, Confirmed).
5. **Permanent deletes are ticked for the user by default**, under the words "safe to delete", with sizes that overstate what will be freed (CLN-1, CLN-2).
6. **Opening Search reads every fixed drive by default**, and a completed first-run wizard turns the AI on with whatever provider it detected (SRCH-3, AI-5, Confirmed in the running app).
7. **Accessibility is thin**: tables are hand-drawn rows with no list semantics, the theme is fixed dark, eight controls in the whole app have accessible names (A11Y-1).
8. **The product has outgrown its frame**: five tabs of which two are the same panel, three places for AI settings, settings spread over a menu, a panel, a wizard and the Advisor, and twenty visualisations of which ten are filed under "For fun".

**Core recommendation.** Keep one product, and frame it as "see what uses your disk, then clean it safely". Fix the six safety and honesty defects first. Then restructure into three workspaces (Explore, Clean, Search) with one Settings page, stop pre-ticking deletes, and drop the word "Uninstall" unless a real Apps view is built. Do not build a full uninstaller: the hand-off is the right scope.

### 3.3 Journeys and where they collide

- **Uninstall an app.** Scan → wait for Advisor → hope the app is over 1 GiB and unused for 180 days → open that finding → Uninstall… → Installed apps opens, name on the clipboard → search there → come back → rescan by hand. There is no path for "I want to remove this specific app".
- **Clean.** Scan → Advisor or Cleaners (already ticked) → Clean up… → review → Clean up now → result card. Collision: the same item is a row in Findings and a part in Cleaners, with one shared tick.
- **Find a file.** Ctrl+F → type → results. Collisions: every drive starts reading; the Filter box beside it does a similar thing to the whole analysis; the AI can set that filter.
- **AI advice.** Settings (one of three places) → Advisor > Ask → Ask → findings appear among rule findings with an "AI" pill, or chat in Ask, or chat in Cleaners.

## 4. User task walkthroughs

**A. Cautious beginner: "free some space".** Starts, wizard opens over the window (6 steps; AI page already filled in if Claude Code or Ollama is installed). Finishes or skips. Clicks the C: card; scan runs. Sees a dense analyser. "Advisor" is the right door but nothing says so. Inside: "2.7 GB can be cleaned · 2.7 GB safe to delete", 7 items already ticked, "Clean up…". Decision points the beginner cannot weigh: what "Run a command" and "How to" mean on a row, why Edge's cache is a "Tip" while Firefox's is ticked, whether "safe" includes their own files. The review does say "Deleted for good". Outcome is clear (measured result card). Risk: they accept a pre-ticked set they did not choose.

**B. Everyday user: "what is big, and find that installer".** Tree View answers the first in one glance. Ctrl+F, type `*.iso`, results in place with sizes. Friction: reading of D:, E:, F:, G: starts unasked; pressing Enter can hit SAF-2; Enter on a result jumps to Tree View instead of opening the file.

**C. Power user: "delete all node_modules over 500 MB on every drive".** Search `node_modules folder: >500mb` works on the scan. Rows from other drives cannot be multi-selected or deleted; each needs "Scan This Folder". No path column sort that is cheap, no regex, no date filter, no saved searches, no exclusions. Multi-select delete in the scan works with one confirmation.

**D. IT/support: "same clean-up on ten PCs, with a record".** "Save as a script" gives a `.ps1` that only measures unless run with `-Run`: good. But it adds unticked admin items (SAF-5), has fewer safety checks than the app, and the log (`cleanup-log.txt`) lists items, not files, with no rotation. No command line for scan-and-export beyond `--screenshot`. CSV export is WizTree-compatible, which helps.

**E. Privacy-conscious: "what leaves this PC, and what is kept".** AI is off unless set up; the disclosure is plain but incomplete (file contents via `read_manifest`, AI-9). Outbound without asking: daily update check, weekly community-cleaner download once the Advisor is opened. Kept on disk: full file listings per scanned root (history, on by default), AI request log in roaming AppData, AI run files, clean-up log. No "clear" for any of them; uninstalling Sprawl keeps history. No privacy cleaners exist yet.

**F. Accessibility-focused: keyboard only, screen reader.** Tabs are reachable (Ctrl+1/2/3/5, Ctrl+F). Arrow keys work in the tree. Column sorting is mouse-only (hit-tested by x position). Rows are text in a panel, not list items: no "row 3 of 400", no selected state, no header association. Advisor rows are buttons without names; tab selection is colour only. Dark theme is forced. Unverified end to end.

**G. Returning user.** Window, view, units and toggles are restored. Advisor section, sort and filter are not. Community cleaners approved earlier lapse silently if upstream changed. "Remembered" holds Keep decisions, which the user may believe protect those folders (SAF-4).

**H. Recovering from a failure.** Partial clean-up: result card separates freed from problems, per item; "See what was removed" opens the log. Stop mid-item leaves that item half-deleted, reported as "Stopped. Freed X". No undo. Stale search result: scan rows open Explorer with no existence check; other-drive rows fall back to the nearest folder with a message. Advisor analysis panic: the tab says "Looking for space to win back..." forever (REL-1).

## 5. Prioritised findings

Template fields are compressed to: area · severity · confidence · who/how often · evidence · impact and why it fails · recommendation · trade-offs · validation.

### 5.1 Safety and honesty (fix first)

**SAF-1. The review says new files are left alone; they are deleted.**
- Clean-up review · **High** · Confirmed.
- Everyone who cleans; every run where a folder gained files after the scan.
- `app/cleanup.rs:504-506`: "…files in use are skipped, and anything new since the scan is left alone." `adv/clean.rs:199-255` lists the folder from disk at run time and deletes each child. Only parts with keep-days spare recent items (`:184, 204`), measured from now, not from the scan.
- A false assurance on a permanent delete. Worst case: an orange finding in Documents, cleaned hours after the scan.
- Recommendation: implement it (skip children created or modified after the scan time, and report them), or delete the sentence today.
- Trade-off: skipping new files leaves caches partly full; say so in the result.
- Validation: unit test with a file added between scan and run.

**SAF-2. Enter/Down in the search box ignores which list a row belongs to.**
- Search · **High** · Confirmed.
- Anyone who searches with other drives loaded (the default) and presses Enter.
- `app/main.rs:356-372` sets `selected = Some(n)` from `rows.first()` whatever its place; `app/tables.rs:843-844` then indexes the scan tree with it. Every other path checks (`tables.rs:790-805`).
- Out-of-range id: the process aborts. In-range id: an unrelated scan item becomes the target of Delete, Open, Copy Path. The confirm box shows the real path and defaults to No, which limits the harm.
- Recommendation: mirror `table_key`: for a place row set `search.more.sel` and clear `selected`/`marked`. Add this path to the review queue's list.
- Validation: scan a small folder, Ctrl+F, `*.iso`, Enter.

**SAF-3. The model-list fetch sends the stored key to any address, over http too.**
- AI settings · **High** (credential exposure; needs a key saved and a non-https or third-party address typed) · Confirmed.
- `adv/llm/models.rs:20-26` attaches `Authorization: Bearer <key>` to `{base_url}/models` with no scheme or host check. The chat path refuses this (`adv/llm/agent.rs:482-491`). The fetch fires when the page opens and 0.7 s after typing pauses (`app/wizard.rs:386-399`). One credential serves every base URL (`adv/config.rs:50-55`).
- Recommendation: route the list through `openai_key()`, store the key per host, fetch on Save or an explicit "Load models".
- Trade-off: one more click to see models for a new server.

**SAF-4. "Keep" hides a suggestion; it does not exclude the folder from a clean-up.**
- Advisor · **Medium** · Confirmed (`adv/clean.rs` never reads memory; `adv/memory.rs:384-396`).
- Scenario: keep `…\Temp\MyTool`; the pre-ticked Temp finding clears it once it is older than 7 days. Tooltip: "Never suggest this, or anything inside it, again" (`app/advisor.rs:2573`).
- Recommendation: pass kept paths to `clean::run` as skips. This is also the cheapest route to a real exclusions feature.

**SAF-5. "Save as a script" exports more than was ticked.**
- Advisor · **Medium** · Confirmed (`app/advisor.rs:1855-1864`).
- With ticks: every built-in "Needs administrator" finding up to amber is appended. With none: every built-in finding up to amber, including found-by-shape caches and Spotify's offline songs. The script lacks the process gate, the final-path check and the post-scan never-list names.
- Recommendation: export exactly the ticks; list anything else as commented-out lines with a note.

**SAF-6. Claude Code is started while Sprawl is elevated.**
- AI · **Medium** · Confirmed that no elevation check exists (`adv/llm/claude_code.rs:107-125`); elevated behaviour not run.
- `claude` is resolved from PATH and `%USERPROFILE%\.local\bin`; the MCP config sits in `%TEMP%`. The app already refuses to start a custom uninstaller when elevated for this reason (`app/advisor.rs:910-913`). "Always run as administrator" is a wizard switch.
- Recommendation: refuse the Claude Code provider when elevated, with a one-line reason; same for PATH-resolved tool commands (`adv/clean.rs:585-587`) unless the tool's path is outside user-writable folders.

**SAF-7. Other accounts' folders are pre-ticked when elevated.** Medium · Code review. Rules use `%SystemDrive%\Users\*\…` (TOML:36, 45, 114, 154…); only tool actions are limited to the current profile (`app/cleanup.rs:124-130`); the open-app check sees this session only (`adv/procs.rs:270-272`). Recommendation: unticked and amber for any path outside `%USERPROFILE%`.

**SAF-8. `closed = "must"` is not enforced when a cleaner names no process.** Medium now, High before privacy cleaners ship · Code review (`app/cleaners.rs:706, 723`; `adv/cleaners.rs:192`). The row still says "only with the app closed". Recommendation: refuse `must` without `running` at load.

**SAF-9. Community import: keyword privacy filter, 64-bit fingerprint, on by default.** Medium · Code review; live files not checked.
- Blocklist of words (`adv/community.rs:292-303`) would pass IndexedDB, attachments, or Opera/Vivaldi/Electron profiles. The never-list covers five browsers and four wallets only (`adv/safety.rs:121-129`). Approval is FNV-64 (`community.rs:105-112`). The weekly download of about 200 files starts when the Advisor first opens (`app/cleaners.rs:339-345`).
- Mitigations in place: amber, inert until "Use this cleaner", never ticked for the user.
- Recommendation: make the fetch opt-in; SHA-256; extend the never-list to messengers and password managers; show a diff when an approved definition changes.
- Validation: run the ignored `fetch_live` test and grep the result for profile and database paths.

**SAF-10. Found-by-shape findings are marked built-in and trusted.** Low-Medium · Code review (`adv/cleaners.rs:510-511`). They can be picked by goal mode and by the no-tick script. Recommendation: a `heuristic` flag that both exclude.

**SAF-11. File contents can go to the AI provider without being disclosed.** Medium · Code review. `read_manifest` sends up to 16 KB of any `readme*`, `license*`, `.nfo`, `manifest.json` and similar (`adv/llm/tools.rs:424-475`); the disclosure names paths only (`app/wizard.rs:69`). Recommendation: disclose, and ask as web lookup does.

**SAF-12. Smaller.**
- Stale place indices after a drive chip is switched off can index the wrong tree (Low, race; `app/search_more.rs:195-196`).
- Helper programs started by bare name (`explorer.exe`, `notepad.exe`) while `adv/hidden.rs:94-95` uses full paths on purpose (Low).
- Tree delete confirms with scan-time counts (Low; Recycle Bin by default).
- `requests.log` is plaintext in roaming AppData, 20 MB, no Clear (Low).

### 5.2 Cleaning

**CLN-1. Deletes are ticked for the user.** Medium · Confirmed in the running app ("7 ticked · 2.7 GB … Sprawl ticked the safe ones for you") and code (`app/cleanup.rs:162-175`).
- Every scan re-ticks all green built-in findings of 1 MB or more, including idle projects' `target`, `bin`, `obj` and multi-GB package caches that need a network to come back.
- A pre-selected, permanent delete under the word "safe" is the pattern the brief warns about. The review step is real, but its content was chosen by the app.
- Recommendation: nothing ticked on first use; one visible "Tick the safe ones" button (it exists); remember the user's own choice per part as "my usual" (also exists).
- Trade-off: one more click per session. Worth it.

**CLN-2. Sizes overstate what will be freed.** Medium · Code review (`adv/rules.rs:540`; `app/advisor.rs:1320-1333`).
- Pattern and keep-days parts report the whole folder (Temp keep-7-days, `*.dmp`, old logs). The headline also counts WinSxS in full though its own text says "the real saving is smaller than shown", the Recycle Bin for all users though only the current user's is emptied, and items that cannot be ticked.
- The result card is measured and accurate.
- Recommendation: size by what the action would remove; headline counts tickable items only; prefix estimates with "up to".

**CLN-3. Risk words promise more than the rule knows.** Medium · Code review (`app/advisor.rs:363-380`).
- Amber reads "Can be re-downloaded or rebuilt" on Recycle Bin and Windows.old, which cannot come back. Green reads "apps rebuild it" on crash dumps. Community and AI parts at amber get the same reassuring label with no "unverified" note; an orange community part reads "Your own files", and the gate box says "These are my own files…".
- Recommendation: four plain levels with per-rule cost text taken from `why`: "Comes back by itself", "Costs a download or rebuild", "Cannot be undone", "Your files". Add a source tag on every row that is not built in: "Community, unverified" / "AI, checked by Sprawl".

**CLN-4. Windows-owned tool items can never run in the app, and the reason shown is wrong.** Medium · Code review (`app/cleanup.rs:125-129`). Recycle Bin, Windows.old, DISM, Delivery Optimization show "Can't be ticked: Another account's". Recommendation: separate "system" from "another account"; let system tools run when elevated.

**CLN-5. No preview of what will actually go, no undo, and two delete models.** Opportunity with safety weight. Tree delete goes to the Recycle Bin; Advisor clean-up is permanent. "Show files" lists the 12 biggest at scan time. The review lists top-level paths in a 190 px box. Recommendation: (a) a "what would go" list computed at review time, with counts; (b) Recycle Bin as an option for orange items.

**CLN-6. The log is thinner than its button.** Low. "See what was removed" opens item paths and totals; no file names, no cleaner name, no rotation (`app/cleanup.rs:621-648`).

**CLN-7. Browser handling is uneven and unexplained.** Low · Confirmed in the running app. Firefox cache: green, ticked, "Delete". Edge cache: grey "Tip · How to". Chrome: tip. Brave: nothing. The cause is the unbuilt carve-outs (plan phase 4), but the user sees an arbitrary difference. Recommendation: one line on tip rows saying why Sprawl will not do it itself.

**CLN-8. Privacy cleaning does not exist.** Observation. No cookies, history, recent files or jump lists; no switch. Space recovery and privacy are therefore not confused today. When phase 5 lands, give privacy its own list, off by default, never mixed into the space total.

**CLN-9. Absent by design, confirmed:** exclusions list, custom paths, schedules, secure wipe, registry cleaning. Only exclusions is a real gap (see SAF-4).

**CLN-10. Smaller.** JetBrains and VS Code say "Close … first" with nothing checking (Low). Stop leaves the current item half-done (Low). "You stay signed in" for Steam's htmlcache is untested (Unverified).

### 5.3 Search

**SRCH-1.** See SAF-2.

**SRCH-2. No persistent index, no incremental update.** Medium against an Everything-class bar · Code review. Everything is re-read each launch; USN replay (plan phase 5) is unbuilt. New files never appear until a rescan. "Changed since the scan" marks exist for the scan root only, need Live Change Pulses on, and are wiped by any delete or rescan (`app/search.rs:56-68`).

**SRCH-3. Opening Search reads every fixed drive, unasked.** Medium · Confirmed in the running app (five drives reading on first open) and code (`app/ui.rs:339`, `app/search_more.rs:173`).
- Without elevation that is a full folder walk per drive, and a tree plus index per drive held until exit. The plan said opt-in per drive.
- Recommendation: default off; first open shows the chips with "Also search D:, E:…" and one "Always" tick.

**SRCH-4. Other-drive results have no age, coverage or error information.** Medium · Code review. No "read at" time, no re-read, unreadable-folder count never shown, no word that removable and network drives are excluded (`app/search_more.rs:496-513`).

**SRCH-5. A drive switched off mid-read is still read and searched; switching it on again duplicates it.** Medium · Code review (`search_more.rs:193-211, 317-320`).

**SRCH-6. The 100,000-row cap for other drives is taken under one sort and kept under another.** Medium · Code review (`search_more.rs:261-278`). After clicking Name the list is "the biggest 100k, alphabetised" while the note still says "the biggest N of M".

**SRCH-7. Sorting and merging can run on the UI thread.** Medium mechanism, cost unmeasured (`app/tables.rs:303-306`, `app/search.rs:220-229`). The code's own comment: "a million matches sort slowly". Validation: sort by Folder with a one-character query on a full drive.

**SRCH-8. Elevated and non-elevated runs answer differently for hard-linked files** (MFT lists one name, the walk lists all). Low-Medium (`core/mft.rs:10-11`).

**SRCH-9. Query edge cases.** Low (`core/search.rs:225-250`): `!` negates even inside quotes; `;` and `|` always split; `>=0` drops empty files; `/` is not a separator; no Unicode normalisation.

**SRCH-10. Interaction gaps.** Opportunity: Enter on a result leaves the tab instead of opening; no key back to the box; highlight covers the first word only; "Nothing found" is one line with no syntax help; a failed drive read is silent; two progress displays for the same reads (top pill and bottom strip, visible in the screenshot); the types pane stays beside results it does not describe.

### 5.4 AI

Boundary result first: **no AI in Search** (Code review: no reference to the llm code in `app/search.rs` or `search_more.rs`). The one crossing is the chat tool `set_filter`, which types into the Filter box.

**AI-1.** See SAF-3. **AI-2.** See SAF-6. **AI-3.** See SAF-11.

**AI-4. "Every request is listed in the advisor's log" is untrue for Claude Code.** Medium · Code review. Only the first prompt is logged (`adv/llm/claude_code.rs:105`); tool answers through the child MCP server are not (`adv/mcp.rs:80-99`). Claude Code is the provider the wizard suggests first.

**AI-5. ## 7. Uninstaller audit

**What exists** (Code review, `adv/facts.rs`):

- A read-only inventory from Uninstall keys (HKLM 64 and 32-bit, HKCU), the current user's Store packages, Steam, Epic, GOG and WSL. ## 8. Cleanup audit

**Categories present** (Code review):

- About 30 built-in rules: developer caches, browser and shader caches, old installers in Downloads, Windows temp, dumps, error reports, Delivery Optimization, Recycle Bin, Windows.old, WinSxS.
- 16 built-in cleaners grouped Browsers, Chat, Games, Media, Developer tools, Windows, Other.

- Community imports, local packs, AI-proposed cleaners: amber at least, inert until approved.
- Tool commands (npm, pip, DISM, cleanmgr…) from the built-in pack only, run hidden from System32 with output kept.

**What is enforced.** Never-list; size within 1 % or 1 MB of the scan; no links above or inside; real-path check; process check twice for must-closed parts; own-files gate in code; fail-closed when Windows' folders cannot be resolved. No path reaches the executor without `safety::check` (reviewer traced the single caller, `app/cleanup.rs:311`).

**Gaps.** No run-time preview, no undo, no exclusions, uneven browser coverage, no privacy cleaners, thin log.

**Recommendation.** Make Cleaners the one cleaning list (section 14), stop pre-ticking, size by action, label by source, and turn Keep into the exclusions list. Do not add schedules or secure wiping.

## 9. Instant search audit

**How it works** (Code review). The scan's names go into one lowercase in-memory index, built off-thread on the first query after each tree change. Other fixed drives are read whole on demand (MFT when elevated and NTFS, otherwise a folder walk) and held until exit. Up to three saved scans can be searched too, marked with their date. Nothing persists between runs.

**Query language.** Space = and; `a|b`; `!word`; `*` `?`; a word containing `\` matches the whole path; `>1gb`, `<10kb`; `folder:`, `file:`; quotes. Case-insensitive substring. No regex, dates, `ext:`. Help is a placeholder and a tooltip.

**Responsiveness mechanisms.** 140 ms debounce; matching on up to 16 threads; cancel flag checked every 65,536 nodes; results dropped unless generation and text still match. Sorting after the match is not cancellable and a header click sorts on the UI thread (SRCH-7). **No timing was measured.** In the one captured run, a two-term query over 457,319 items showed results while five drives were still reading; that is a single observation, not a benchmark.

**Results.** Name (match highlighted), Size, Allocated, Modified, Folder; sortable; footer "N found | M items searched"; matches lit on the map. Scan rows get the full menu including Delete; other-drive rows get Show in Explorer, Copy Path, Scan This Folder.

**Coverage and freshness.** Fixed drives only. No word in the view that removable and network drives are excluded, how old a drive read is, or how many folders could not be read. New files appear only after a rescan.

**Privacy.** The query is kept in memory only; nothing about search is stored or sent.

**Verdict.** As "search inside the scan" it is good and distinctive (sizes, map highlight, safe delete). As an Everything replacement it is not there: no persistent index, no live updates, session-long memory per drive. Position it as the former, fix SAF-2 and the default, and decide later whether USN replay is worth building (section 17).

**Evidence still needed.** Query latency and sort stalls at 1 M+ matches; memory per loaded drive; non-elevated walk of all drives on a laptop; F3-style race reachability.

## 10. Advisory AI audit

**Entry points** (Code review).

| Entry | Where | Sends | Returns | Control |
|---|---|---|---|---|
| Analysis "Ask <model>" | Advisor > Ask | Report (120 biggest folders, 60 findings, 25 apps with last use, memory), then tool answers | Checked findings with "AI" pill, summary, rejected list, cost | Click to start; Stop |

**Can the AI act?** No. Traced by the reviewer: the strongest path to a deletion is `report_finding` → checks → orange, unticked → user ticks → Clean up… → own-files box → Clean up now, with `safety::check` again at run time. **Injection surface.** Folder names, README contents and web snippets reach the model unfiltered; stored preferences are fed back into later prompts. The limits are the checks and clicks above. Acceptable, with AI-10 fixed.

**Data.** No redaction: user names in paths go as they are. No telemetry. Outbound calls in total: provider, DuckDuckGo (asked), model lists, GitHub update check, community download, localhost probes.

**Does it earn its place?** Yes in two roles: naming unknown folders, and proposing cleaners for apps the rules do not know. Weakly in a third: "suggest what to clean" duplicates goal mode and the safe-tick button. Remove the chat card from Cleaners' header (AI-9) and keep one chat, in Ask.

**Boundary with search.** Respected. Keep `set_filter` out of the Search box, and never add a search tool for the model.

- Settings: one page behind the gear. AI: a single "Ask AI" panel inside Clean, off by default. Search: the box filters the tree in place; no other drives.
- For: beginners and everyday users. Cost: loses File View, other-drive search, History, most views. Risk: power users leave.

### B. Balanced (recommended)

```
[ Explore ]  [ Clean ]  [ Search ]  [ Over time ]                          ⚙
Explore:   Tree | Files sub-views, types pane, map (6 views), colour modes
Clean:     Cleaners by app + "Other findings"; foot with ticks and Clean up…
           right-hand drawer: details of the open item; "Ask AI" drawer (if on)
           "Apps" sub-view: installed apps with size and last use → Open Installed apps…
Search:    one box; "This scan" by default; drive chips opt-in and remembered
           action: "Narrow Explore to this" (the filter, shown as a chip)
Over time: growth list, history slider, Tideline
```

- Settings: one page, eight sections (6.3). File menu shrinks to scan sources, exports and exit; row actions live in the context menu and a details drawer.
- AI: only in Clean (drawer and "AI" pills) and Settings. Never in Search.
- Benefits: each tab is one job; the duplicate Cleaners tab, the second search box and three AI editors disappear. Cost: a real refactor of `advisor.rs`. Risk: existing users relearn four tabs.

### C. Expert

```
Left rail: Explore · Files · Search · Clean · Apps · Over time · Log
Main: dense table; Right: details/inspector; Bottom: map (collapsible)
Command palette (Ctrl+K); every list has column chooser, multi-select, export
```

- Settings: page plus `settings.ini` documented; per-view saved filters; exclusions editor; script export and a `--report` command line.
- AI: an inspector tab. Search: independent pane with regex and saved queries.
- For: power and IT users. Cost: the most UI to build and to make accessible. Risk: beginners drown.

**Recommendation: B.** It removes every structural duplication found, keeps the analyser intact, and leaves room for C's inspector and command line later without another reshuffle.
