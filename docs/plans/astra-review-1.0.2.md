# Sprawl 1.0.2 safety review

Reviewed local `main` at `621418b3db1fca5e02537099d55c2118e77d877d` on 19 November 2026. The highest-priority findings are an elevated settings write on the update path, a Windows-menu permission check that still fails open, elevated MCP reads outside the displayed scan, and duplicate linking that can discard data while promising no loss. I also found a drive-root inventory regression and two cases where “Recycle” or “Clean up” understates permanent deletion. Locations below are relative to `crates/` and refer to this commit.

## 2. Fixes from the Opus whole-codebase audit

**Verdict — changes requested.**

1. **High — unknown elevation still opens the Windows menu with its switch off.** `sprawl/src/admin.rs:128`, `sprawl/src/shellmenu.rs:173`. The shared caller uses `is_elevated()`, which maps error to false. After passing, it calls `show(..., true)`. The new fail-closed query inside `show` therefore has no effect on the normal entry point. Shell extensions can load in the elevated app. The configured uninstaller uses the same shared gate immediately before spawn at `sprawl/src/advisor.rs:1443`. **Smallest acceptable fix** — treat query failure as elevated in the shared gate and pass the actual privileged setting through to the final operation. Cover unknown elevation plus switch off through the caller. Claude Code and Codex independently reread elevation at launch and require their actual permission flag.
2. **Medium — compression verifies the old tree and can proceed after the live check fails.** `sprawl-advisor/src/safety.rs:775`, `sprawl/src/cleanup.rs:647`, `:727`, `sprawl-advisor/src/clean.rs:253`. An ordinary game tree with no reparse bits passes. A recorded link on the ancestor chain gives ThroughLink, and a nested recorded link gives LinksInside with that node’s path. A link added later, an unreadable subtree, or a file with another hard-link name need not appear as a link in that tree. Even when live measurement returns None, the recursive command runs. A shared file's storage can change outside the reviewed game. Conversely, a visible WOF data leaf is also called a junction/link because the predicate tests every reparse bit. **Smallest acceptable fix** — require a successful live compression eligibility check, distinguishing verified WOF data from redirecting/unknown tags, checking link counts and refusing incomplete traversal. Keep the verified scope stable through execution or operate on individually verified files. Add plain-game, nested-link, WOF-leaf and changed-scope fixtures.
3. **Medium — a menu reread can be registered after the next scan has already started.** `sprawl/src/state.rs:331`, `sprawl/src/shellmenu.rs:157`, `:187`, `sprawl/src/commands.rs:1044`. Clearing the receiver at scan start fixes the usual ordering, and disconnect clears the Delete gate. While a new scan runs, a menu command on the still-present old tree can install another receiver. Its delayed result is applied by matching path, including to an overlapping new tree. **Smallest acceptable fix** — refuse in-scan menu operations while a scan is active, or attach the originating scan generation to every result and check it at delivery.
4. **Medium — Codex can still hang after the process exits or report incomplete output as success.** `sprawl-advisor/src/llm/codex.rs:139`, `:228`, `:235`. A helper holding stdin open without draining it can leave the writer blocked at the unbounded join before the 30-second timer starts. A partial stream containing an agent message can also be accepted after a nonzero exit, without a terminal success event. The early-exit test looks for a substring anywhere in newline-terminated output. **Smallest acceptable fix** — apply cancellation/deadline to all pipe operations and require a parsed, complete terminal event and successful exit. Bound retained stdout/stderr and stop readers with the process tree.

The highlight fix checks lowercase width per character and checks slice boundaries at the drawing site (`sprawl-core/src/query.rs:851`, `sprawl/src/search.rs:476`). The wildcard matcher preserves the previous character/range cases and memoizes suffix states (`sprawl-advisor/src/clean.rs:1070`). The targeted tests passed. The button now retains an explicit Gone count for more than three outcome types, and compression/shrink are classified before generic Tool. Section 4 records what that count still omits.

## 3. Elevated Sprawl and non-administrator MCP clients

**Verdict — changes requested.**

1. **High — even a denied call can cause fresh privileged reads.** `sprawl/src/bridge.rs:84`, `sprawl-advisor/src/facts.rs:149`, `:211`, `sprawl-advisor/src/llm/tools.rs:308`. With a screen tree but no published facts yet, any syntactically valid request can gather application manifests, recent items and program-use information, including Windows Prefetch, before the disk decision is enforced. Creating Tools also creates a fresh Never list, which consults known folders and exclusion settings. The report generator can do that again. **Smallest acceptable fix** — dispatch restricted requests before lazy I/O. Use a restricted query interface over already published tree/facts/report values only, and return “not ready” when required facts are absent.
2. **Medium — growth and owner queries exceed the displayed tree.** `sprawl-advisor/src/llm/more_tools.rs:127`, `:163`, `sprawl-advisor/src/llm/tools.rs:416`, `sprawl-advisor/src/llm/report.rs:167`. Growth reads History from disk and can return a former child’s name and size after it disappeared or was excluded. Owner lookup accepts a path outside the tree, and the generated report can list last-use information for unrelated apps. Even an ordinary-user-readable History file exceeds the advertised screen-only scope. **Smallest acceptable fix** — gate growth as a disk tool, require membership for owner queries, and publish only screen-scoped app facts/reports to restricted clients. List children, largest, by type and search can use the tree and precomputed facts. Findings and Cleaners return published text. Set filter queues a revision-checked UI change.
3. **Medium — the switch does not enable the advertised elevated scan.** `sprawl-advisor/src/mcp_scan.rs:309`, `sprawl-advisor/src/mcp.rs:311`. With the switch on, the bridge admits scan calls but the production app index still returns PASS_TO_SERVER for every elevated app. A normal client then scans with its own rights. With the switch off, the explicit denial is returned. A default test index omits this production condition. **Smallest acceptable fix** — carry the authorized disk decision into the app index for scan_path/status/list, or narrow the setting’s promise if client-side scanning is intended. Exercise the real app-index configuration for both switch states.
4. **Low — a held process handle narrows the PID race but does not bind it to the pipe.** `sprawl-advisor/src/pipe.rs:122`, `:126`. SID, native image path and elevation are queried on one process object. Between obtaining the numeric client PID and opening that object the original client can exit. Ordinary disconnection usually leaves nobody to read an answer. A surviving pipe endpoint and PID reuse by another matching Sprawl process are the relevant residual conditions. Repeating the PID query alone does not prove identity. **Smallest acceptable fix** — retain the image check and require the security context of the actual pipe message to establish the same SID and elevation before granting privileged reads. Fail closed on inability to query or revert. I did not reproduce PID reuse. [Windows named-pipe client security context](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-impersonatenamedpipeclient)

The HKLM value is per SID, uses the 64-bit registry view and defaults off on a failed read. Local-only pipe, same-account and exact-image checks remain. Unknown client elevation selects the restricted branch, and unknown app elevation requires the switch. The three direct denials for scan tools, background-tree answers and manifest reads are present. A lower-privilege client that cannot verify the server's image/account can lose bridge availability. I did not test cross-integrity connectivity.

## 4. Design branches affecting destructive-action disclosure

**Verdict — changes requested.**

1. **High — “To the Recycle Bin” can include permanent removal of link objects.** `sprawl/src/cleanup.rs:1392`, `sprawl-advisor/src/clean.rs:666`, `:792`, `:804`. An Orange or forced Remove containing a junction cannot be recycled whole. During the item pass, ordinary files go to the bin, but an eligible junction or symlink is deleted as a link. Its target survives. Explorer cannot restore the removed link from the bin. The group, button and all-binned checkbox promise recycling, even though separate explanatory text mentions removing links. **Smallest acceptable fix** — in recycling mode leave such links in place with a note, or safely recycle the link objects. That makes the existing promise true even for links first seen at execution.
2. **Medium — privacy deletion disappears from the permanent count.** `sprawl/src/cleanup.rs:1428`, `:1436`, `sprawl-advisor/src/clean.rs:576`. A privacy-only selection says “Clean 1 privacy item”. With Bin, Tool, Link and a privacy set it can say only “Clean up now”. Set deletes database/side files by handle without the bin. The privacy card and checkbox give separate consent, but the button still understates its outcome. **Smallest acceptable fix** — give privacy sets an explicit permanent-delete label in their group and include them in the irreversible count in both button forms. Count sets as sets.
3. **Low — the lead sentence contradicts the outcome groups.** `sprawl/src/cleanup.rs:1192`. A compression-only or shrink-only run can say “Deleted for good” above a row promising in-place change. An owner command has tool-defined deletion semantics. **Smallest acceptable fix** — derive the lead, headings and button from the same outcome list. Keep the tool’s permanent-deletion warning when its program controls disposal.
4. **Medium — Coverage promises completeness the scan cannot establish.** `sprawl/src/coverage.rs:51`, `:63`, `:106`, `sprawl-core/src/mft.rs:444`. “Every file is counted” includes records the MFT builder deliberately omits, even before configured exclusions. An MFT tree with zero recorded errors does not prove every folder was opened. Elevated scans can also fall back to walking. A combined scan can mix methods and local/remote roots, but one network flag and one aggregate method describe them all. **Smallest acceptable fix** — describe records included in the selected roots, show the recorded error count, and qualify WOF/allocated-size estimates and elevation by actual method or root. Label mixed coverage explicitly. The captured skip list really is the one supplied to Progress. CSV appropriately disclaims original coverage. Render multiline paths line by line at `:127` because `esc` replaces newlines before the attempted replacement.
5. **High — “Copies made links lose nothing” overlooks NTFS named streams.** `sprawl/src/cleanup.rs:1205`, `sprawl-advisor/src/dupes.rs:83`, `sprawl-advisor/src/clean.rs:989`, `:1007`. Two copies can have identical default-stream bytes while only one carries a named stream containing application metadata or user data. Sprawl compares the default streams, creates a hard link to the keeper, then permanently deletes the original copy. If it was the last name for that file, its unique stream is lost. The reviewed confirmation and the Link group give no warning. **Smallest acceptable fix** — hold the replacement if either file has a named data stream or its streams cannot be verified. Compare on the held files at execution. [Windows file streams](https://learn.microsoft.com/en-us/windows/win32/fileio/file-streams)

For ordinary Remove/Clear/Match rows the executor uses the same bin predicate as the review. Ordinary bin failure or insufficient room holds the data. Duplicate linking shares the keeper’s file across the selected names, so future edits affect all of them. Move guidance has no in-app move executor. A permitted second-click conversion explicitly becomes Orange-or-higher Remove with forced recycling. Shrink and compression are typed in-place actions. The ordinary own-files, privacy, held-item and changed-definition gates remain in the execution path.

After an earlier success, `got.or(old)` preserves the old tree and report, and the failure text is in the no-report branch. A user can still see candidates after the new read found no readable root. The partition itself grants no cleanup authority. **Smallest acceptable fix** — invalidate the old selection/report on failure or show it explicitly as stale and disable execution until a successful reread. At `:1180` report the open failure without assuming elevation would cure it.

## 6. 1.0.2 reliability

**Verdict — changes requested.** History’s deletion path remains confined to verified snapshot entries. The mandatory speed guard needs a fixture it can prove it owns and a measurement that remains a folder benchmark.

1. **Medium — the benchmark removes a pre-existing path.** `sprawl-core/tests/speed_guard.rs:28`. Its name contains only the PID, and startup recursively removes that path even though this run did not create it. A reused PID or pre-existing folder can lose unrelated data. An ignored removal error can leave old contents mixed into subsequent traversal. **Smallest acceptable fix** — exclusively create a fresh temporary directory, retry collisions, fail on setup errors, and remove only that acquired directory.
2. **Medium — release timing can fail for reasons unrelated to a folder-walk regression.** `sprawl-core/tests/speed_guard.rs:53`, `sprawl-core/src/lib.rs:194`, `sprawl-release/src/main.rs:125`. From an elevated build, scan_auto can read the whole NTFS volume’s MFT for the tiny folder. 3. **Low — the History cap can keep redundant tied snapshots.** `sprawl-advisor/src/history.rs:192`, `:330`. Saving a full and folders-only snapshot normally gives both the same second.
