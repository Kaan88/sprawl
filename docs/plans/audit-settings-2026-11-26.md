# Settings audit, 2026-11-26 (GPT-6.2 Sol, high, source-only)

**Settings has ten sections, but Save, Cancel, Reset, and “read-only” don’t mean the same thing across them.** Fix the cases where a saved protection can be lost or ignored first: the privacy-cleaner switch, failed or stale saves, and the migration that can opt a new profile into drive reads and scan history.

This was a **source-only audit**. No files were changed, no state-changing commands were run, and no app, tests, or screenshot runs were launched. Layout and screen-reader observations below distinguish what the XAML proves from what still needs a live check.

## Current structure

**Options → Settings** (`Ctrl+Shift+S`) opens General. The left rail switches sections; **Save** and **Cancel** are global. Every section except Theme has **Reset this section**. Some buttons act immediately. The table uses the actual storage key where one exists; action-only rows name their action or data store. ## Findings

### High

| Finding | User impact and concrete fix |
|---|---|
| **H1. Turning privacy cleaners off can leave them available in the current report.** [wizard.rs:648](crates/sprawl/src/wizard.rs#L648) · [commands.rs:681](crates/sprawl/src/commands.rs#L681) · [cleaners.rs:1911](crates/sprawl/src/cleaners.rs#L1911) · [cleanup.rs:705](crates/sprawl/src/cleanup.rs#L705) | Save changes the flag, but report invalidation is in the startup-only `apply_settings`. The displayed group and selection read the cached report; cleanup can still take its privacy selections after the switch is off. The separate review consent still applies. On Save, invalidate both Advisor and Cleaners reports, clear privacy ticks and consent, drop results from older in-flight reads, and check the current flag again at execution. |
| **H2. “Settings saved” can be false, and a second instance can silently undo a protection.** [settings.rs:20](crates/sprawl/src/settings.rs#L20) · [settings.rs:45](crates/sprawl/src/settings.rs#L45) · [wizard.rs:1305](crates/sprawl/src/wizard.rs#L1305) · [commands.rs:962](crates/sprawl/src/commands.rs#L962) | Save ignores write errors and replaces the entire file from its in-memory map. With two instances, A can save a new `scanExclude`, then B can close and overwrite it while saving only its window position. Future scans read the exclusion from disk. Return write errors, keep the draft open on failure, and serialize read–merge–write using only changed keys. Distinguish missing settings from unreadable settings; don’t overwrite the latter from defaults. |
| **H3. The legacy migration can turn on scan history and other-drive reads on a fresh profile.** [settings.rs:32](crates/sprawl/src/settings.rs#L32) · [main.rs:199](crates/sprawl/src/main.rs#L199) · [commands.rs:695](crates/sprawl/src/commands.rs#L695) | Any nonempty INI is treated as old. A fresh profile that saves window placement but has never chosen History or Search scope qualifies on its next launch: missing `snapshots` becomes on and missing `oSearchDrives` triggers selection of fixed drives. Stamp new files with a schema version on their first write. Migrate only positively identified legacy data; ambiguous files should not gain scan or retention permissions. |
| **H4. Screenshot mode is not a read-only Settings sandbox.** [main.rs:295](crates/sprawl/src/main.rs#L295) · [main.rs:746](crates/sprawl/src/main.rs#L746) · [wizard.rs:987](crates/sprawl/src/wizard.rs#L987) · [wizard.rs:1116](crates/sprawl/src/wizard.rs#L1116) · [wizard.rs:1259](crates/sprawl/src/wizard.rs#L1259) | The INI writer, automatic updates, alert scheduling, and normal snapshot saves have guards. But startup still runs data-folder and credential migrations before the flag is set, and Settings can write AI config/credentials, alter Explorer registration, change Advisor memory, clear logs or History, and restore registry values through unguarded paths. Establish screenshot mode before startup migrations, use isolated stores, and refuse external writes at the action and storage boundaries—not just at `settings.ini`. |
| **H5. “Never touch” promises more than the cleaner enforces.** [prefs.rs:218](crates/sprawl/src/prefs.rs#L218) · [cleanup.rs:900](crates/sprawl/src/cleanup.rs#L900) · [cleanup.rs:1571](crates/sprawl/src/cleanup.rs#L1571) · [clean.rs:423](crates/sprawl-advisor/src/clean.rs#L423) | A kept child can sit below the root of an external cleanup command. The root check does not catch that case, and the review itself warns the tool may remove kept items. Refuse an external command when its verified scope overlaps a kept path or cannot be established. Until then, state the exception on the Settings row, not just at the final review. |

## Proposed structure

Keep one Settings entry. Keep contextual shortcuts where they’re useful, but have them open the same editor or invoke the same action rather than implement another version of a preference.

```text
Settings
├─ General
│  ├─ Startup and after-scan navigation
│  └─ Size display and visible panels
├─ Theme
│  ├─ Sample, preset dropdown, copy/paste, restore default look
│  └─ Colour · Shape · Feel · Text and space
├─ Scanning
│  ├─ Scan on drive pick, skipped folders, Explorer integration
│  └─ Administrator startup and advanced permissions
├─ Search
│  ├─ Drive and saved-scan scope
│  ├─ Recent searches, pins and clear
│  └─ Result columns and advanced result limit
├─ Treemap
│  ├─ Palette, labels, sizing and free space
│  └─ Motion, 3D, shading, tilt and edge smoothing
├─ Cleaning
│  ├─ Recycle Bin, saved selections and old-scan warning
│  ├─ Keep list
│  ├─ Privacy cleaners and backup locations
│  └─ Advisor rules, duplicate limits and uninstaller
├─ History and alerts
│  ├─ Scan history, retention, disk use and clear
│  └─ Low space, folder growth and optional daily scan
├─ AI and connections
│  ├─ Provider, model, effort, credentials and web permission
│  ├─ AI request log, remembered AI results and Claude Code integration
│  └─ Offline, updates and community downloads
└─ Data and recovery
   └─ Open both data folders; restore preferences with an explicit scope
```

Use compact labelled rows and stock controls. Put long lists on bounded, paginated subpages; keep immediate data actions separate from the Save/Cancel draft. **Still unverified:** rendered fit at default/minimum size and DPI, live keyboard and screen-reader behavior, and the real Windows side effects of the traced code paths.
