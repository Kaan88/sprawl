# Sprawl 1.0.2 safety re-review

Reviewed local `main` at `69dff06` on 19 November 2026. The seven implementation commits are `1c5821a`, `9e65d86`, `77cca26`, `c9c8cd7`, `078ed1c`, `56d0b45` and `dd4a5a4`. The comparison is with the [30 findings at 621418b](astra-review-1.0.2.md). Source locations below are relative to `crates/` at the reviewed head.

**Changes requested.** The most consequential remaining cases are deletion of an old directory that replaced a reviewed one, a package purge authorized by incomplete output, privileged reads from the restricted MCP report, and loss of named-stream data during duplicate linking. The Codex checks also leave a gap between the configuration inspected and the process that receives the report.

## 1. Fixes for the 1.0.1 findings

1. **S1 #1 · High · Fixed for the elevated update settings write.** `sprawl/src/settings.rs:54`, `sprawl-advisor/src/lib.rs:91`, `sprawl-advisor/src/store.rs:9` and `:60`. Update bookkeeping and shutdown now use a writer that holds the checked parent chain, exclusively creates its temporary leaf, flushes it and renames that file by handle. A pre-existing temporary link cannot become its output. Failed publication disposes of the opened file. Exports using this helper refuse name collisions. No further change for the original update path. Two other per-user mutations in the reviewed call paths are listed below.
2. **S1 #2 · Medium · Partly fixed.** `sprawl-install/src/setup.rs:58`, `:132`, `:202`. COM obtains the actual principal and action collection. An unreadable field, different SID, group or service principal, or extra action stops migration. The single action only has to end in `sprawl.exe` and take `--check`. An unrelated installation with that basename qualifies. More importantly, the folder's `DeleteTask` receives only a name. A replacement after the last check need only be deletable by this user. Its principal and action are never inspected. Running unelevated limits the damage but does not establish ownership. **Minimum:** leave the shared task for manual retirement if replacement cannot be excluded. If presenting a migration candidate, match the full known legacy executable path and its expected registration. [Task Scheduler deletion contract](https://learn.microsoft.com/en-us/windows/win32/api/taskschd/nf-taskschd-itaskfolder-deletetask)
3. **S1 #3 · Medium · Partly fixed.** `sprawl-advisor/src/clean.rs:180`, `:205`, `:891`, `:977`. A moved-in old folder at a *new* path stays. If an old folder replaces a reviewed directory at the *same* path after the scan, the membership callback still returns true. Its old files can pass freshness and be permanently deleted even though the review never saw them. Both the whole-folder prewalk and item pass use this predicate. **Minimum:** hold a changed directory unless its reviewed object identity is known to match. Skipping changed directories until the next scan also closes this case.
4. **S1 #4 · High · Partly fixed.** `sprawl-advisor/src/clean.rs:294`, `:379`, `:410`, `:1857`. NuGet now selects global packages. The other recognized tools also get location checks, but the parser receives the last **12 display lines**, already clipped to 200 characters each. For a long conda list, a second existing cache can appear in discarded early lines. The retained lines can contain the reviewed cache and only absent alternatives. Validation then authorizes an all-cache clean. Even a complete answer describes the probe process: its directory pins are dropped and the cleanup process resolves configuration again. **Minimum:** use complete bounded machine output, rejecting any truncation, and bind the cleaning invocation to the verified destination with pins held. Hold tools whose effective destinations cannot be constrained. The test at `:2540` passes prepared strings directly to the parser and misses this production boundary. Saved PowerShell scripts also emit the original command at `sprawl-advisor/src/export.rs:53` and `:69`. Omit these actions from runnable exports unless the script can enforce their scope.
5. **S1 #5 · Medium · Fixed for namespace escape.** `sprawl-core/src/local.rs:43`, `:64`. Both UNC forms go through the same component checks, and the normalized spelling is checked before long-name lookup and again afterwards. The previously reported dot-server input is refused. **New, low:** `:58` also rejects every share name beginning with a dot. A previously scannable share such as `\\nas\.photos` is refused even though its server and share are distinct ordinary components. Allow a leading dot in a non-dot-only share name while retaining the namespace and normalization checks.
6. **S1 #6 · High · Partly fixed.** `sprawl-advisor/src/memory.rs:419`, `:425`, `sprawl/src/commands.rs:860`. A lock, malformed TOML or unknown AppData location now holds the pending item. But following a dangling link at the memory filename also returns NotFound and is accepted as an empty list. A Keep saved after confirmation can disappear from the decision when its backing file becomes unavailable this way. The analogous settings reader already distinguishes a dangling leaf at `sprawl-advisor/src/exclusions.rs:46`. **Minimum:** accept absence only after verifying the expected parent chain and absent leaf, and hold the target on ambiguous policy. Retain any additional Keeps already observed during the batch.
7. **S1 #7 · Medium · Partly fixed.** `sprawl-core/src/walk.rs:397`, `:407`, `:449`. The comparison includes the volume GUID and preserves ordinary case. Both sides still use lossy UTF-16 decoding. Distinct native names containing unpaired surrogates can become identical replacement characters, so the check can admit the wrong resolved descendant after an ancestor changes. Enumeration itself uses the checked handle. **Minimum:** join, trim the separator and compare native UTF-16 units on both sides. Convert names for display only after admission.
8. **S1 #8 · High · Fixed.** `sprawl-core/src/walk.rs:396`, `:406`, `:605`. The volume root and queued suffix get exactly one separator. The regression tests cover a drive-root suffix with no leading separator, a folder-root suffix with one, and listing a real direct child with the checked handle. No further change for the join.
9. **S1 #9 · Medium · Partly fixed.** `sprawl-advisor/src/exclusions.rs:67`, `:108`, `:114`, `:149`. The conservative short-name parent receives aliases, overlapping mappings work in both directions, and a failed connection lookup for a recognized network letter is handled conservatively. But a zero drive mask, an unavailable letter or an unknown drive type does not enter the failed list. A skip saved on a disconnected mapped drive can therefore leave its still-reachable UNC spelling unprotected. **Minimum:** distinguish a positively identified local drive from one whose kind or mapping is unknown. Apply the conservative network policy to the latter.

   **New, medium:** `sprawl-advisor/src/exclusions.rs:156` compares normalized components, then slices the original UNC string at the other spelling's *byte length*. Case-equivalent Unicode spellings of different UTF-8 lengths can give the wrong suffix or panic during settings expansion. Derive the remaining components from the original path by component count and test unequal-width spellings.
10. **S1 #10 · Medium · Partly fixed.** `sprawl-advisor/src/safety.rs:597`, `:623`, `:698`, `sprawl-advisor/src/reg.rs:142`. A trailing-dot host and an unfamiliar host serving a recognized local share now protect its backing folder. A missing registry value plus absence from a best-effort enumeration still becomes `Share::Absent`. That enumeration skips oversized values and returns partial results on error. A temporary share also need not have a persistent registry entry. An unfamiliar alias for such a local Documents share can therefore lose the personal-data protection. **Minimum:** use the local Server service's live share lookup and distinguish an explicit missing share from access/query errors, or return Unknown for an unproved absence. [Windows share lookup](https://learn.microsoft.com/en-us/windows/win32/api/lmshare/nf-lmshare-netsharegetinfo)

**Other per-user writes checked for S1 #1.** These predate the seven fixes. Both are reachable in code whose neighboring writes were reviewed.

- **High · `sprawl-advisor/src/llm/mod.rs:267`, `:272`.** The request log still creates directories, rotates a name and opens a predictable path for append. An elevated provider session with a redirected log can append the prompt to another file. **Minimum:** skip logging and rotation when elevated or elevation is unknown, or use a checked append/rotation implementation that also verifies leaf identity and link count.
- **Medium · `sprawl/src/search_query.rs:655`.** Clearing the last search still removes `searches.txt` by path. A redirected parent can make elevated Sprawl delete an unrelated file with that name. **Minimum:** publish an empty history with the checked writer, or remove a verified leaf through its handle.

## 2. Fixes from the Opus audit

1. **S2 #1 · High · Fixed.** `sprawl/src/admin.rs:122`, `:138`, `sprawl/src/shellmenu.rs:179`, `sprawl/src/advisor.rs:1432`. An unknown token now requires the administrator switch. The menu passes the actual switch to its second check, and the configured uninstaller uses the same fail-closed gate at dispatch. The decision-table test passed. No further change for this finding.
2. **S2 #2 · Medium · Fixed for the in-app recursive link case.** `sprawl-advisor/src/remedies.rs:129`, `:142`, `:160`, `:171`. Sprawl inspects the live tree, handles a WOF data file separately from a link, and passes exact, pinned file arguments to compact. Existing multiply linked files are skipped. A newly discovered junction no longer becomes a recursive compact target. The fixture checked that an ordinary file was compressed and an external hard-link alias stayed uncompressed.

   **New, medium:** `sprawl-advisor/src/remedies.rs:130` gathers exclusions but completes a detailed walk with an empty `Progress` before testing them. A folder newly skipped below a game directory can still be enumerated and its files probed before compression is refused. Stop is also first consulted after this walk. **Minimum:** reject any known exclusion intersection before enumeration, carry exclusions into the walk and connect it to the operation's cancellation. **Remaining export route, medium:** `sprawl-advisor/src/export.rs:53`, `sprawl/src/advisor.rs:4076`. An eligible exported compression finding can still emit its recursive command. A link that appears before manual execution misses the in-app checks. Omit that executable action from exports or implement the same selection at execution.
3. **S2 #3 · Medium · Fixed.** `sprawl/src/shellmenu.rs:165`, `:187`, `sprawl/src/state.rs:331`. The shared scan-row command refuses while a scan is running. Starting a scan drops an earlier receiver. Search paths passed with `in_scan = false` do not schedule scan-tree rereads. No further change for the reported ordering.
4. **S2 #4 · Medium · Partly fixed.** `sprawl-advisor/src/llm/codex.rs:325`, `:343`, `:410`, `:453`. The stdin writer no longer holds up a join. Jobs, capped buffers, a post-exit deadline, a parsed completion event and a successful exit address the original hang and ordinary partial response. The parser still accepts a completion *anywhere* in the retained prefix. Stdout that exceeds the cap is silently discarded, including any subsequent failure. A wrapper that exits successfully after such a stream can turn an incomplete record into an accepted answer. **Minimum:** reject a truncated or failed read and require the successful terminal event for the answer's turn after its message. Check Stop while waiting for final output.

## 3. Elevated Sprawl and non-administrator MCP clients

1. **S3 #1 · High · Partly fixed.** `sprawl/src/bridge.rs:88`, `sprawl-advisor/src/mcp.rs:410`, `sprawl-advisor/src/llm/report.rs:154` and `:23`. The restricted branch no longer gathers application facts or constructs ordinary tools. Once facts exist, however, a restricted non-CSV `scan_report` calls `build → unexplained → Never::default_list`. That reads personal-folder configuration and the exclusion file with the app's token. The test checks response text and misses these side effects. **Minimum:** omit this derived section from restricted reports or supply a previously published result. Exercise restricted reporting with fresh settings/known-folder reads forbidden.
2. **S3 #2 · Medium · Partly fixed.** `sprawl-advisor/src/mcp.rs:383`, `sprawl-advisor/src/facts.rs:187`, `sprawl-advisor/src/llm/tools.rs:429`, `sprawl-advisor/src/lib.rs:160`. Growth and manifest reads are denied. Owner lookups and app/Recent projection now test tree membership. That test folds component case. On a case-sensitive directory, an app installed at a different, case-only sibling of a displayed folder can pass projection and have its name and last-use date returned. **Minimum:** use exact observed membership for restricted app locations and queries, build the restricted ownership index from admitted locations and use the resolved tree node's path. History already has a case-preserving tree lookup. The report's separate I/O issue is S3 #1.
3. **S3 #3 · Medium · Fixed.** `sprawl/src/bridge.rs:76`, `sprawl-advisor/src/mcp.rs:379`, `sprawl-advisor/src/mcp_scan.rs:309`, `sprawl-advisor/src/mcp.rs:311`. An authorized app index can serve scan, status and list calls. Without authorization an elevated app returns the handoff before polling jobs or reading History, and the client process handles it. Authorized scans use the folder walk. The real app-index test passed here as an ordinary user, so its **unelevated** expectation ran. I did not exercise the elevated handoff. No further change for the reported switch behavior.
4. **S3 #4 · Low · Partly fixed.** `sprawl-advisor/src/pipe.rs:70`, `:85`, `:93`, `:172`, `:214`. The new token check closes the original simple PID-reuse case for an ordinary client. It requires the correct SID and combines token elevation with the peer process check. **The revert failure path is correct:** the thread opens a query handle, immediately reverts even if opening failed, and aborts the process on failed revert. Dispatch and token interpretation occur after a successful revert. For the stronger claim of verifying *each writer*, identification level alone selects static context tracking here. A connection reused after a security-context change can retain the opening context. Also, a buffered line on this byte pipe need not correspond to the last kernel read. **Minimum:** for privileged replies require one request per separately authenticated connection, without transferring the endpoint, or use dynamic tracking and one bounded pipe message per request with identity tied to that read. Keep the abort. The same-account fixture exercises one writer and one read. [CreateFile security tracking](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) · [Pipe impersonation](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-impersonatenamedpipeclient) · [Revert failure](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-reverttoself)

## 4. Disclosure before destructive actions

1. **S4 #1 · High · Fixed.** `sprawl-advisor/src/clean.rs:808`, `:937`, `:950`, `:977`. A bin-mode root link, child directory link or child file link is held with a reason. A known link also disqualifies a whole-folder move. Ordinary bin failure has no permanent-delete fallback. No further change for this finding.
2. **S4 #2 · Medium · Partly fixed.** `sprawl/src/cleanup.rs:1442`, `:1459`, `:1527`. The heading makes disposal explicit and avoids a promise of erasure. Counts are in sets and survive condensation. **The button by itself is still ambiguous:** “Delete 1 for good and 1 privacy item” can imply that only the first bypasses the bin. The privacy-only form just says “Delete 2 privacy items”. **Minimum:** use “Delete 2 privacy items without the Recycle Bin”, or “Delete 1 item and 1 privacy set without the Recycle Bin”, and retain the same delete clause in the condensed button. No promise about recovery is needed.
3. **S4 #3 · Low · Partly fixed.** `sprawl/src/cleanup.rs:1404`, `:1411`, `:1424`. Compression-only and shrink-only leads are correct. With Gone, Bin and Compress selected together, the lead still says everything outside the bin is deleted for good, then says compression deletes nothing. Privacy plus Bin plus Link reaches the same branch. **Minimum:** describe only the explicitly counted Gone/privacy groups as bypassing the bin and the Bin group as recyclable. Keep the separate tool and in-place clauses.
4. **S4 #4 · Medium · Partly fixed.** `sprawl/src/coverage.rs:55`, `:62`, `:74`, `:119`, `:141`. The MFT description now excludes metadata, zero errors is qualified for a single MFT root, mixed network coverage has counts, and multiline values keep their breaks. A local unelevated walk on exFAT still says an administrator scan *will* use the file table. An unreadable local folder can still be described as readable on restart, and multiple local NTFS roots can fall back to a walk. Drive type is also measured when Details opens, so remapping a letter can relabel an old scan. **Minimum:** say that elevation *may* enable the MFT on eligible local NTFS volumes and *may* improve access. Retain scan-time network/method facts or mark the per-root details unknown.
5. **S4 #5 · High · Partly fixed.** `sprawl-advisor/src/clean.rs:1124`, `:1148`, `:1166`, `:1185`. Listing streams on the held files detects static missing, extra and unequal streams. **Reading by stream name does not establish equality through replacement.** Pins stabilize the ordinary filenames, but Windows maintains sharing modes per stream. A metadata writer sharing delete can change a named stream after its bytes were compared. The short-lived reads are closed before the original's last name is deleted. Even the 1 MB limit is taken from the earlier listing, while the read itself is unbounded. **Minimum:** refuse files with named streams or an inconclusive listing. If stream membership cannot be kept stable through disposal, preserve the original or decline linking. Supporting streams with equal content requires a stable set and stable, bounded reads through commit. The passing fixture contains no concurrent stream writer. [Windows stream sharing and delete access](https://learn.microsoft.com/en-us/windows/win32/fileio/file-streams)

## 5. Codex, Markdown and Cleaners

1. **S5 #1 · Medium · Partly fixed.** `sprawl-advisor/src/llm/codex.rs:47`, `:151`, `:226`, `:251`, `:382`. **No to both preflight questions.** Disabling discovered MCP servers by name and refusing unfamiliar tools catches real configuration drift. It does not enforce report-only execution. The accepted list includes generic execution and helper-agent creation. Tool names do not establish their behavior in this build or a later build, and helper permissions are never checked. The preview omits the model selected for the real run. The check also accepts a changed JSON item with no recognized `tools` field, and accepts blank server output as an empty list.

   The checks run with a fresh `CODEX_HOME`. The real process inherits the login home. The installed 0.170.0 help describes skipping that home's `config.toml` and retaining it for auth. It gives no guarantee that every other home-dependent input is equivalent. Testing two filenames with `.exists()` cannot establish equivalence, and errors there look like absence. Thus a different effective model, configuration or implementation can expose actions the preview never accounted for. I did not observe a model executing a tool. **Minimum:** refuse this provider for report-only mode until the actual invocation enforces a tool/server-free boundary, or use a text-only provider interface with no tool executor. A preflight can supplement that boundary when tied to the same executable, home, model, configuration and mode.

   **New, high · `sprawl-advisor/src/llm/codex.rs:94`, `:114`, `:127`.** Fresh directory names are exclusive but their identities are retained only as paths. Parent checks happen after recursive creation and do not pin the chain. If a run directory is renamed and replaced by an unrelated ordinary directory, Drop recursively removes the replacement. This is reachable with elevated rights when the provider switch is enabled. **Minimum:** create under checked, pinned parents and retain ownership through disposal. If identity cannot be established, leave the directory. Never recursively delete an unverified replacement.
2. **S5 #2 · Medium · Fixed for the original descendant escape.** `sprawl-advisor/src/llm/contain.rs:40`, `:50`, `:60`, `:106`, `:115`. Claude Code and Codex start suspended. Successful job enrollment precedes resume. Failure kills the suspended child, and job termination or last-handle close covers descendants. The helper-held-pipe fixture passed.

   **New, medium · `sprawl-advisor/src/llm/codex.rs:168`, `:260`, `:382`, `:390`.** The four probe invocations have individual timeouts but never check Stop. A user who cancels during preflight can wait through more probes and have a successful preflight followed by logging and sending the prompt before the first Stop check. **Minimum:** pass Stop into the probe wait, end its job on cancellation and check again immediately before launching and sending the real prompt.
3. **S5 #3 · Medium · Partly fixed.** `sprawl/src/ui.rs:196`, `:262`, `:276`, `:283`. The reported separator-before-wildcard case, balanced URL parentheses and wide-table fallback are repaired. Inline parsing still treats legal filename punctuation as markup. For example, the literal path `C:\[draft](old).txt` displays as `C:\draft (old).txt`, and `C:\~~draft~~.txt` loses both tilde pairs. A wildcard within a component can still start emphasis. Links are escaped text runs with no navigation action. **Minimum:** recognize and emit drive/UNC path spans, including their glob components, literally before interpreting inline markup. Include these path-shaped link and strike cases in the renderer tests.
4. **S5 #4 · Medium · Fixed.** `sprawl/src/cleaners.rs:132`, `:311`, `:342`, `:359`, `:1219`. A failed completed reread or disconnected worker clears the own-read report and its generation's selections, review and consents. The old candidates are no longer actionable after failure. An unrelated scan's selections survive. A partial success names omitted folders with the Windows error. The previous result remains visible while a reread is pending, as the queue states. No further change for the reported post-failure behavior.

## 6. Reliability

1. **S6 #1 · Medium · Fixed for startup collisions.** `sprawl-core/tests/speed_guard.rs:29`. Exclusive directory creation retries a collision, so a reused PID or pre-existing candidate no longer causes deletion at startup. **Residual, low:** `:44` removes the pathname on Drop. A fixture renamed and replaced while the test runs can still cause recursive removal of a directory this run never acquired. **Minimum:** retain a checked directory identity through teardown or leave the fixture when ownership is uncertain. This matters particularly for elevated release builds.
2. **S6 #2 · Medium · Fixed.** `sprawl-core/tests/speed_guard.rs:51`, `:95`, `:108`. Known unelevated status is required to time automatic scanning. Inventory always stays on the fixture, timings are interleaved, and a slow result must repeat against a new baseline. The separate fixture run passed. No further change for this finding.
3. **S6 #3 · Low · Fixed.** `sprawl-advisor/src/history.rs:318`, `:324`, `:335`. Under cap pressure, one surviving entry per root is protected. A full snapshot wins a same-second tie with folders-only and the filename breaks remaining ties. The tied folders-only entry can be evicted. The cap can still be exceeded by the required newest entries. No further change for the reported tie.

**New, medium · Test fixtures introduced with S1, S4 and S5.** `sprawl-advisor/src/clean.rs:1887`, `:2168`, `:2542`, `sprawl-advisor/src/llm/codex.rs:568`. These four tests repeat the original speed-guard mistake. They recursively delete a predictable PID-based name before acquiring it. A stale or unrelated directory at that name is removed during an ordinary workspace test. **Minimum:** use an exclusively created fixture directory in each test, retry collisions and clean up only the acquired directory.

## Verification and limits

- I read the named queue section from the gitignored file on disk, the prior report and the follow-up prompt. I compared the changed functions with their callers and execution paths. Detailed reads covered the writer, ownership check, directory freshness and identity, package probe/output boundary, exclusion mapping, compression, pipe and report dispatch, confirmation text, stream handling, Codex checks/jobs, Markdown parser, Cleaners invalidation, benchmark and History cap. I followed supporting registry, scan, display, export and retention helpers where those fixes depend on them. Generated bindings, unrelated features and the rest of the codebase were outside this pass.
- I ran `cargo test --release --workspace --no-fail-fast` **once**, after a Windows principal check confirmed an unelevated shell. **381 passed, 0 failed, 10 ignored**: app 82/1 ignored, advisor 220/6, core 63/2, installer 16/0 and speed guard 0/1. The remaining targets and doc-tests had zero tests. The suite exercised its own fixture writes, deletes, renames, hard links and compression. Its drive-root regression test lists one direct child's entries. Some junction assertions are conditional on fixture creation.
- I separately ran the ignored speed guard with the same non-administrator check. It passed on 1,093 folders and 2,186 files: plain listing 27.89 ms, inventory 11.75 ms and automatic scan 11.40 ms. This is one machine's observation. The ten ignored count above is for the workspace command.
- For Codex I checked the installed version and help for exec and debug prompt-input. The help commands returned their output with restricted-profile warnings about temporary CLI aliases. I did not run a model session or the ignored installed-preflight test. I inspected the same-account pipe and Task Scheduler tests and their implementation. There was no elevated or cross-account pipe session, induced revert failure, task registration/deletion, or elevated shell handoff in this pass. Live stream/configuration races and WinUI rendering were assessed from source. The package test used prepared output strings. No real package cache was purged.
- I did not start a whole-drive scan, perform a cleanup on user data, invoke a UAC flow, run a separate release build, format source, commit, push or release. This re-review is a separate file so the original findings and their historical line numbers remain available.
